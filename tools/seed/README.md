# Наполнение демонстрационного стенда

`task seed` вызывает только HTTP API и подходит для отдельного compose-стенда. `task seed:kind` создаёт временные
port-forward в выделенный kind `blood-supply`, запускает ту же утилиту и закрывает только свои процессы.

Состав: 10000 единиц C01 дополнительно к стартовому набору имитатора, недостающие синтетические нормативы,
три CSV аналитика, опубликованная годовая оценка, прогноз на первый день следующего месяца, план и заявка врача.
Нормативы добавляются только при их отсутствии и под общей блокировкой обычного сценария записи.
Имеющиеся значения не перезаписываются. CSV распознаются по SHA-256; планы и заявка используют ключи идемпотентности.

Входные параметры: `BS_SEED_INVENTORY`, `BS_SEED_DEMAND`, `BS_SEED_PLANNING`, `BS_SEED_MATCHING`,
`BS_SEED_KEYCLOAK`, `BS_SEED_AIST`, `BS_SEED_PASSWORD`, `BS_SEED_SERVICE_SECRET`.
В окружении inventory должен быть `BS_ENV=local`, `ci` или `demo`. Операция нормативов требует `IT_SERVICE` (ADR-0036).
Токены, ответы с номером случая и содержимое CSV не выводятся в журнал.

Утилита не выбирает клинический вариант, не подтверждает задания и не удаляет записи. При ошибке уже завершённые
операции остаются сохранёнными; повтор пропускает существующие данные. Прогноз создаётся как синтетический ИНТ-02,
без прямой записи в Kafka. Команда не запускалась по решению владельца; подтверждены сборка и статический анализ.
