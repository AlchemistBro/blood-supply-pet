Источник: контекст проекта v11, ПР6 АМ и ПР6 DDD (РТУ МИРЭА, ИНБО-30-23). Идентификаторы зафиксированы, новые не вводятся.

| Роль | Код в Keycloak | Что делает |

| Оператор клинической организации | `CLINIC_OPERATOR` | Вводит годовой расход, смотрит запас, запускает внеочередное обновление из АИСТ-М, подтверждает передачу от клиники-источника, корректирует распределение прогноза |
| Территориальный аналитик | `TERRITORIAL_ANALYST` | Загружает CSV (профиль районов, история расхода, доли район → клиника), подтверждает публикацию версии оценки |
| Дежурный смены | `DUTY_OFFICER` | Получает эскалации (не подтверждено в срок, C03 молчит), решает перевозку вручную. Введён в прототипе саги |
| Внешняя ИТ-служба | `IT_SERVICE` | Учётные записи и роли (в Keycloak), версии правил подбора по документам заказчика, чтение журнала аудита |

Каждый пользователь привязан к клинике (`clinic_id` в токене), кроме аналитика, дежурного и ИТ-службы.

Дополнительные понятия прототипа саги (не объекты канона, но часть единого языка):

- **Остаток источника** — агрегат `transfer.source_stock`: клиника × вид, доступные, зарезервированные, защищённый объём с версией.
- **Водяной знак** — версия снимка запаса из `inventory`, по которой построена проекция; показывается как «данные на HH:MM».
- **Спецификация замены** — группа, резус, фенотип, минимальная годность и версия правила O15, посчитанные `matching` при выборе врача; по ней `transfer` проверяет равноценность замены (ADR-0011).

Омонимы, которые нельзя смешивать:

- *Дефицит плана* (`planning`) — нехватка до целевого запаса клиники. *Дефицит заявки* (`matching`) — заявку не покрыть допустимыми вариантами. O11 хранит оба с типом и основанием.
- *Единица* в `inventory` — запись учёта АИСТ-М (только чтение). *Единица* в `transfer` — ресурс Закрепления (локальная копия с версией).

## Формулы и правила расчёта

- Норматив (FR012, FR013): `Kср = Kгод / 12`, `N = Kгод / 360`, но не меньше объёма одной единицы.
- «Запас ниже норматива» (FR014): фактический объём вида в клинике < N.
- Фоновая потребность (FR019): `D(r, k, g, p) = V(r, k, p) × s(r, g)` для видов с признаком группы; `V` — объём района по доле населения от `B(k, p)` из истории расхода; `D_c = Σ_r w(r, c) · D`.
- Целевой запас (FR021, FR023): `target = norm + background + emergency`.
- Защищённый объём источника (FR025, NFR013): норматив + фоновая потребность источника за период + подтверждённые обязательства. Передача не может опустить доступный остаток ниже него.
- Полнота плана (NFR014): если пригодные источники есть, покрытие ≥ 90 %, непокрытое — в реестр дефицита всегда.
- FEFO (FR015): пригодные единицы упорядочиваются по возрастанию срока годности; при подборе — годность на момент прибытия.
- Подбор (FR030, FR034): шаг 1 допустимость по правилам O15 и ограничениям O08 (предпочтительный вариант, затем разрешённые замены, исключения запрещают); шаг 2 ранжирование по приоритету правила, сроку годности, времени доставки, расходованию защищённого запаса. Нехватка запаса не разрешает нарушать клинические ограничения: нет варианта — дефицит.
