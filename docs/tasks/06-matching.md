# Этап 6. Заявка врача и подбор по правилам (ФП4)

Цель: `matching` закрывает FR029–FR035, FR043, FR047, FR051, FR052; NFR009, NFR016, NFR017. Экраны врача. ИНТ-05 через `inventory`.

## Чеклист

### Данные
- [ ] Миграции по словарю ПР6 (7 таблиц) + `clinical_request_patient` (конверт `libs/k1seal`, ADR-0020) + проекции `unit_projection`, `delivery_estimate_projection`, `obligation_projection` + outbox/inbox/audit_local.
- [ ] Справочник правил O15: сид из `libs/testdata` (10 демо-правил с `basis_document = "ДЕМО…"`, версии, `valid_from/valid_to`); OpenAPI для ИТ-службы: `GET /rules`, `POST /rules/{code}/versions`.

### Подбор
- [ ] Шаг 1 допустимость (FR030): предпочтительный вариант (та же группа/вид), затем разрешённые замены из правил, исключения запрещают; ограничения O08 (`IRRADIATED`, `NO_GROUP_SUBSTITUTION`, …) применяются строго; нехватка запаса не разрешает нарушать ограничения.
- [ ] Шаг 2 ранжирование (FR034): приоритет правила, срок годности на момент прибытия (FEFO), время получения (местный = 0), расходование защищённого запаса источника (`is_deficit_stock_used`); `explanation` текстом с факторами (NFR009); `stock_watermark`.
- [ ] Конкретные единицы варианта (FR031) без закрепления; доступное количество; время получения (FR032); пометка дефицитного запаса (FR033).
- [ ] Нет допустимого варианта → `RequestDeficitRecorded(NO_ALLOWED_VARIANT)`, статус заявки «дефицит».
- [ ] Выбор врача (FR043): местный вариант → статус «выбран местный вариант» (закрепления в АС нет); удалённый → спецификация замены (ADR-0011) + `OpenObligation` (`choice_id` = id выбора, `fallback_sources` = следующие варианты по рангу, `confirm_window` по срочности, `patient_case_sealed` — конверт `libs/k1seal`, ADR-0020) → статус «создано задание»; реакция на `TransferRejected/Expired/Broken` → следующий вариант или дефицит; на `TransferShortfallRecorded` → задание на остаток.
- [ ] Отмена заявки врачом → `CancelObligation` → закрепления сняты.
- [ ] OpenAPI: `POST /requests`, `GET /requests?clinic=`, `GET /requests/{id}`, `GET /requests/{id}/patient-case` (отдельно, аудит `READ_PATIENT_CASE`), `GET /requests/{id}/variants`, `POST /requests/{id}/select`, `POST /requests/{id}/cancel`.

### Закрепление за пациентом в АИСТ-М (FR051, FR052, NFR017)
- [ ] `transfer` после `Confirmed` по заявке врача → команда `AllocateUnitsToPatient` (ИНТ-05) в `inventory.commands` (идемпотентный ключ = O07 id + версия).
- [ ] `inventory`: inbox → `aist_outbox_message` → воркер отправки в C01 с backoff и тем же ключом → `acknowledged_at` → `PatientAllocationAcknowledged`; при отмене/нарушении `ReleasePatientAllocation`.
- [ ] UI: статус «закрепление передаётся в АИСТ-М / подтверждено АИСТ-М» на задании и заявке.
- [ ] Тест NFR017: обрыв связи с имитатором и перезапуск `inventory` → ровно одно закрепление в C01.

### UI врача
- [ ] «Новая заявка»: номер случая, вид, количество, срочность, группа и резус, фенотип, ограничения (чекбоксы кодов + параметр); валидация.
- [ ] «Варианты»: карточки по рангу: источник (местный/удалённый), вид и группа, доступно, время получения, пометка «расходует защищённый запас», объяснение «почему допустим и почему здесь»; кнопка «Выбрать»; время данных о запасе.
- [ ] «Мои заявки»: статусы, статус задания live, дефицит с причиной, отмена.
- [ ] Номер случая показывается по отдельному запросу (кнопка «показать») с записью в аудит; оператору источника — только в карточке задания при подтверждении.

### Тесты
- [ ] Юнит: таблица правил → ожидаемые допустимые варианты и порядок; ограничения побеждают нехватку.
- [ ] Интеграционные: выбор → O07 PENDING у источника; `TransferRejected` → следующий вариант; роль `TERRITORIAL_ANALYST` на `/patient-case` → 403 и аудит `DENIED`; каждое чтение номера случая в журнале.
- [ ] e2e: сценарий врача из защиты.

## Критерий выхода
Врач вводит заявку, видит ранжированные варианты с объяснением, выбирает удалённый; оператор источника видит задание с таймером,
подтверждает; закрепление уходит в имитатор АИСТ-М ровно один раз; врач видит «перевозка запрошена».

## Проверка «тест действительно проверяет»
Убрать применение ограничения `NO_GROUP_SUBSTITUTION` → юнит-тест допустимости падает. Убрать идемпотентный ключ ИНТ-05 → тест NFR017 находит дубль.
