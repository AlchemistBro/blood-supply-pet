# Этап 4. Территориальная потребность (ФП2)

Актуальная проверка 24.10.2026: обычные и PostgreSQL-сценарии пройдены в общем локальном прогоне
без Docker. [Результаты и пропуски Kafka](../perf/acceptance-status.md),
[безопасность и права](../architecture/security-local-2026-10-24.md).
Браузерная, сквозная и платформенная приёмка остаются открытыми.

Цель: `demand` закрывает FR016–FR020, FR045, FR046; NFR008, NFR009. Экраны аналитика.
Модель: `docs/domain/glossary.md` раздел «Формулы».

## Чеклист

На 24.10.2026 реализованы три загрузчика CSV, история и версии долей, расчёт
оценки с явным выбором входов, публикация аналитиком и события через outbox.
Связи с исходными версиями и строки клиник сохраняются в одной транзакции;
повтор публикации не создаёт второе событие. Web поддерживает multipart с CSRF
без JavaScript, построчные ошибки, расчёт, публикацию и отклонение с причиной.
Сохранённые ошибки доступны по ссылке файла, три демо-шаблона скачиваются из UI.
Опубликованная и отклонённая версии неизменяемы; повтор отклонения не дублирует аудит. Тесты
пройдены, включая откат пакетного сохранения оценки; сборка, vet и линтеры выполнены.

### Данные и расчёты
- [ ] Миграции по словарю ПР6 (11 таблиц) + outbox/inbox/audit_local.
- [ ] Приём CSV трёх видов (`DISTRICT_PROFILE`, `CONSUMPTION_HISTORY`, `CLINIC_SHARE`): multipart, SHA-256 (повтор того же файла отклоняется), проверка формата, обязательных полей, источника, периода, сумм долей (= 1 ± 0,0001) по району; построчные ошибки в `file_row_error`; статус `ACCEPTED/PARTIAL/REJECTED`.
- [ ] История расхода из файла или из `ConsumptionExportPublished` (`history_source`).
- [ ] Расчёт оценки (FR019): `B(k,p)` → объём района по населению → `D(r,k,g,p) = V × s(r,g)` для видов с `is_group_applicable` → `D_c = Σ w(r,c)·D`; строки `clinic_demand`; `estimate_history_link`; `DemandEstimateCalculated`.
- [ ] Версионирование: `CALCULATED → PUBLISHED` только аналитиком (`confirmed_by`), `REJECTED`; `DemandEstimatePublished` со строками; `ClinicSharesPublished`.
- [ ] OpenAPI: `POST /files` (multipart), `GET /files/{id}`, `GET /files/{id}/errors`, `GET /history`, `GET /shares/versions`, `POST /estimates` (рассчитать за период), `GET /estimates`, `GET /estimates/{id}`, `POST /estimates/{id}/publish`, `POST /estimates/{id}/reject`.
- [ ] Шаблоны CSV и описание формата в `docs/ui/csv-formats.md`; `libs/testdata` генерирует корректные и битые файлы.

### UI аналитика
- [ ] «Загрузка файлов»: drag-and-drop, выбор вида, результат проверки, таблица отклонённых строк с причинами, скачать шаблон.
- [ ] «История расхода», «Доли район → клиника» (версии с основанием).
- [ ] «Версии оценки»: рассчитать за период, просмотр строк по клиникам/видам/группам, входы версии (файлы, доли, периоды), «Подтвердить публикацию» / «Отклонить».

### Тесты
- [ ] Юнит: формулы на эталонном наборе (ручной расчёт в тесте); суммы долей; округления.
- [ ] Интеграционные: повтор файла отклоняется; `PUBLISHED` без `confirmed_by` невозможен (CHECK); событие доходит до `planning` (проекция).
- [ ] Свойственные: Σ по клиникам потребности района = потребность района (с точностью округления).

## Критерий выхода
Аналитик загружает три CSV, видит отклонённые строки, рассчитывает версию, публикует; `planning` показывает новую версию как доступную для плана.

## Проверка «тест действительно проверяет»
Убрать проверку суммы долей → тест файла с долями 1,2 падает.
