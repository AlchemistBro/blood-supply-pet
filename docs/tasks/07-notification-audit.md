# Этап 7. Уведомления, эскалации, аудит

Цель: `notification` закрывает FR044, FR049 (уведомления), эскалации дежурному; `audit` закрывает NFR008, NFR016 как
неизменяемый журнал. Экраны дежурного и ИТ-службы.

## Чеклист

### notification
- [ ] Подписка на `transfer.events`, `planning.events`, `inventory.events` (`StockBelowNorm`); правила: `ObligationOpened` (по выбору врача) → письмо оператору источника со ссылкой на задание, видом, объёмом, срочностью (без спецификации и номера случая, FR044); `TransferRejected/Expired/Broken/Cancelled` → врач и оператор (FR049); `EscalationRaised` → дежурный; `StockBelowNorm` → оператор клиники.
- [ ] Адресаты: из Keycloak Admin API по роли и клинике (кэш) — ADR-0016 при необходимости; в демо — Mailpit.
- [ ] Доставка: таблица `notification` со статусами и повторами; сбой письма не меняет задание (FR044); метрики.
- [ ] Шаблоны писем (text + html) в строгом служебном стиле; русский язык.

### audit
- [ ] Consumer `audit.events` → `audit_record` с `seq`, `prev_hash`, `hash`; роль БД только INSERT; `task audit:verify` и `GET /internal/verify` проходят цепочку и находят разрыв.
- [ ] OpenAPI (роли `IT_SERVICE`, `DUTY_OFFICER`): `GET /records?module=&action=&object=&user=&from=&to=`; экспорт CSV.
- [ ] `web` пишет `LOGIN`, `LOGOUT`, `ACCESS_DENIED` через HTTP `POST /records` в `audit` с ретраем (у `web` нет БД; ADR-0017). `READ_PATIENT_CASE` пишет только `matching` в транзакции выдачи номера (ADR-0020); `web` его не дублирует.

### UI
- [ ] Дежурный: «Эскалации» (не подтверждено в срок, C03 молчит/отказал, АИСТ-М недоступна при экстренной) с действиями «Назначить перевозку вручную» (ввод `transport_ref`), «Закрыть с комментарием»; «Все задания», «Запас всех клиник».
- [ ] ИТ-служба: «Журнал аудита» с фильтрами и проверкой цепочки, «Правила подбора» (версии), «Состояние интеграций» (последние `sync_run`, ошибки шлюза, DLT).
- [ ] Mailpit ссылка в dev-панели.

### Тесты
- [ ] Интеграционные: письмо уходит после `ObligationOpened`; Mailpit недоступен → задание не меняется, повтор позже; эскалация по таймеру → письмо дежурному.
- [ ] Аудит: подмена записи в БД → `verify` сообщает разрыв с номером `seq`; все значимые действия этапов 1–6 присутствуют (чеклист действий в тесте).

## Критерий выхода
Демо: выбор врача → письмо в Mailpit оператору; таймер истёк → эскалация дежурному письмом и на экране; `task audit:verify` зелёный, после ручной порчи записи — красный с указанием места.

## Проверка «тест действительно проверяет»
Убрать `prev_hash` из хеша → тест подмены не находит разрыв.
