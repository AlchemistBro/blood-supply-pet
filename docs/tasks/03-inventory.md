# Этап 3. Запасы полностью (ФП1)

Цель: `inventory` закрывает FR001–FR015, FR050; NFR001, NFR003, NFR015. Экраны запаса для оператора.

## Чеклист

### Данные и расчёты
- [ ] Миграции: `annual_consumption`, `stock_norm`, `unit_status_dict`, представление `actual_stock` с индексом; `aist_outbox_message` (структура для этапа 6).
- [ ] Синхронизация ИНТ-01: расписание изменений (`CHANGES`), суточный снимок CSV (`DAILY_SNAPSHOT`) с сверкой и исправлением расхождений + запись в аудит, `ON_DEMAND` по запросу оператора (FR050) с результатом и временем, `UNIT_CHECK`; `sync_run` как источник водяного знака.
- [ ] Расчёт норматива (FR012, FR013): ввод `annual_consumption` оператором → новый `stock_norm` (`is_current`), `StockNormPublished`.
- [ ] «Запас ниже норматива» (FR014) по `actual_stock` против `norm_ml`; событие `StockBelowNorm` (для уведомлений, этап 7).
- [ ] FEFO (FR015): эндпоинт пригодных единиц, упорядоченных по сроку; фильтры вид/группа.
- [ ] `StockSnapshotPublished` после каждого успешного `sync_run` (по клинике × вид × группа) с водяным знаком.
- [ ] `ConsumptionExportPublished` из снимка (FR045, по согласованию) — флаг.
- [ ] OpenAPI: `GET /clinics/{id}/stock`, `GET /clinics/{id}/units?kind=&group=&fefo=true`, `GET /units/{id}`, `GET /units/{id}/history`, `PUT /clinics/{id}/annual-consumption`, `GET /clinics/{id}/norms`, `POST /clinics/{id}/sync` (FR050), `GET /sync/last`, `GET /sync/runs`.

### UI оператора
- [ ] «Запас клиники»: таблица вид × группа: единиц, литров, ближайший срок, норматив, индикатор «ниже норматива»; время обновления и кнопка «Обновить из АИСТ-М» с результатом.
- [ ] «Единицы»: список FEFO с фильтрами, карточка единицы с историей состояний (FR008).
- [ ] «Годовой расход и норматив»: форма ввода Kгод по видам, расчёт Kср и N, история нормативов.
- [ ] Дежурный видит запас всех клиник (сводная таблица).

### Тесты
- [ ] Юнит: формулы норматива с минимумом одной единицы; FEFO; версии (старая не перезаписывает новую).
- [ ] Интеграционные: синхронизация 100 изменений ≤ 5 мин (NFR001) при интервале 30 с; снимок исправляет расхождение и пишет аудит; `ON_DEMAND` только оператором своей клиники.
- [ ] k6 черновик: `GET /clinics/{id}/stock` p95 ≤ 2 с на 100 000 единиц (NFR003).

## Критерий выхода
Экран запаса клиники показывает норматив, подсветку «ниже норматива», время обновления; «Обновить из АИСТ-М» возвращает результат;
имитатор выдаёт единицу → через ≤ 5 мин (в демо ≤ 30 с) она исчезает из запаса, а `transfer` получает `UnitWithdrawn`.

## Проверка «тест действительно проверяет»
Отключить проверку `source_version` → тест «старая версия не перезаписывает новую» падает.
