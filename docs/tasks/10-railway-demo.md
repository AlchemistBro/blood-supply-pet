# Этап 10. Публичный демо-стенд на Railway

Статус: подготовлена конфигурация, 24.10.2026. Публичное развёртывание ожидает приёмки этапа 9,
аккаунта, бюджета и разрешения на публикацию образов. Решение владельца от 20.10.2026: демо выкладывается на Railway.
Цель: рабочий публичный URL, по которому можно пройти демо-сценарий из README без установки чего-либо.

Подготовлены [профиль и порядок запуска](../../deploy/railway/README.md), переменные всех сервисов,
общий HTTPS-вход с закрытыми путями Keycloak, шаблон realm, readiness, отдельные образы инфраструктуры
и генерация секретов/SQL новой установки. Эти файлы не создают ресурсы и не подтверждают работу стенда.

## Что нужно учесть заранее

Railway запускает сервисы из Docker-образов или репозитория и даёт управляемый PostgreSQL. Kubernetes-манифесты
из `deploy/k8s` там не применяются, поэтому стенд описывается отдельно, а образы берутся из ghcr.io (этап 1+).
Актуальные возможности и цены Railway проверить на момент этапа: от них зависит, сколько сервисов влезет в бюджет.

## Решения подготовки ([ADR-0026](../adr/0026-railway-demo.md))

| Вопрос | Варианты | Предварительная рекомендация |
| --- | --- | --- |
| Профиль нагрузки | а) все 9 сервисов и 3 имитатора; б) объединение процессов | а), сохраняются существующие проверяемые границы, потребление ещё не измерялось |
| Kafka | своя в контейнере (KRaft, один брокер) или облегчённая замена (Redpanda) | Один брокер в контейнере с томом; контракты не меняются |
| Keycloak | в контейнере с импортом realm | Да, `start --optimized`, база `keycloak` в том же Postgres |
| PostgreSQL | один экземпляр с томом, база и роль на сервис (ADR-0005 сохраняется) | Подготовлен профиль образа PostgreSQL; HA не заявляется |
| Доступ | публичный URL только у edge, web и OIDC за ним; остальное в частной сети | Да, административные и dev-пути закрыты |
| Данные | отдельное наполнение через API и согласованный сброс | Наполнение подготовлено; сброс не реализован, перезапуск процесса данные не удаляет |
