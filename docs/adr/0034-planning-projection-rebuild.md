# ADR-0034. Восстановление проекций планирования из локального журнала

Статус: принят, 24.10.2026.

`planning` сохраняет после каждого принятого изменения полный снимок изменённой строки проекции
в `planning_projection_journal` той же транзакцией, что и inbox. Журнал содержит только разрешённые
поля проекции: исходные Kafka-сообщения, фенотип и зашифрованный номер случая туда не копируются.
При обновлении существующей базы текущие проекции становятся исходными снимками журнала.

`task planning:rebuild` восстанавливает последний снимок каждого ключа одной транзакцией,
под общей блокировкой с расчётом плана и записью проекций. Порядок блокировок: общая блокировка,
затем строки проекции. Операция пишет аудит, сохраняет inbox, планы, дефициты и outbox;
новых заданий и защищённых объёмов не публикует. Команда требует `BS_DB_URL` базы planning.

Журнал восстанавливает проекцию после её ошибочного изменения или удаления, но не заменяет резервную
копию всей базы. При повреждении самого журнала требуется восстановление БД или контролируемое
повторное чтение Kafka с исходных смещений. Метаданные, ранее не сохранявшиеся проекцией, из старых
снимков не появляются; они заполняются очередными событиями.
