# ADR-0002. Микросервисы по карте контекстов сразу

Статус: принят, 20.10.2026.

## Контекст

ПР6 защищает модульный монолит и обосновывает его требованием NFR004 (одна транзакция) и NFR002 (30 с без сети).
План миграции (схемы 10–14) описывает целевые микросервисы и дорожную карту 0a–7 через промежуточный монолит.
Владелец решил строить целевую архитектуру сразу: сервис на контекст, с прицелом на прод.

## Решение

Восемь сервисов по карте контекстов: `inventory`, `demand`, `planning`, `matching`, `transfer`, `logistics-gateway`,
`notification`, `audit`, плюс `web`. Контекст «Передачи и обязательства» (`transfer`) выделен из ФП3: он владеет O07, O18
и Остатком источника и является оркестратором саги. NFR004 обеспечивается внутри одного сервиса одной транзакцией и
частичным уникальным индексом; межсервисной распределённой транзакции нет. NFR002 обеспечивается расчётом плана внутри
`planning` по локальным проекциям, без сетевых вызовов в цикле.

## Последствия

- Проекции (запас, оценки, статусы) с версиями и водяным знаком вместо JOIN; UI показывает «данные на …».
- Больше эксплуатационных единиц: compose и k8s с самого начала, стандарт сервиса (probes, метрики, миграции).
- Границы контекстов из учебных документов становятся физическими; домен K1 изолирован в `matching`.
- Монолитная промежуточная стадия (этап 0a–0b дорожной карты) пропускается.

## Условия пересмотра

Если объём работы для одного разработчика оказывается непосильным, допустимо временно объединить `notification`
и `audit` в один процесс `platform-sidecars` без изменения контрактов.
