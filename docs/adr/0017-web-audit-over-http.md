# ADR-0017. Сервис web пишет аудит по HTTP

Статус: принят, 20.10.2026. Изменено ADR-0020: `READ_PATIENT_CASE` пишет `matching` при выдаче номера;
`web` пишет `LOGIN`, `LOGOUT`, `ACCESS_DENIED`.

## Контекст

Остальные сервисы пишут аудит в outbox своей транзакции (NFR008). У `web` нет базы: он BFF без состояния.
Но именно `web` фиксирует вход, выход и отказ в доступе. Чтение номера случая (NFR016) фиксирует `matching`
в транзакции выдачи номера (ADR-0020).

## Решение

`web` отправляет записи аудита в `audit` по `POST /records` служебным токеном (роль `SERVICE`, клиент `services`).
Запись принимается той же цепочкой хешей. Поле `details` проверяется: ключи `patient_case_no`, `full_name`,
`snils`, `phenotype`, `password` приводят к отказу 400.

`web` пишет `LOGIN`, `LOGOUT` и `ACCESS_DENIED` (в том числе отказ в чтении номера случая, если `web` отказал сам,
до запроса к `matching`). `READ_PATIENT_CASE` `web` не пишет: эту запись делает `matching` в одной транзакции
с выдачей номера (изменено ADR-0020; прежде здесь было «сначала запись в аудит из `web`, затем показ значения»).

## Последствия

- Единственное исключение из правила «аудит через outbox»; оно ограничено сервисом без базы.
- `audit` не стоит на пути показа номера случая: атомарность чтения и аудита обеспечивает транзакция `matching` (ADR-0020).
- Обычные пользователи писать в журнал напрямую не могут: проверено e2e-тестом.
