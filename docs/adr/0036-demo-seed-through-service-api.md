# ADR-0036. Наполнение синтетического стенда через HTTP

Статус: принят, 24.10.2026.

`task seed` работает через API, не пишет в базы сервисов и не публикует сообщения в Kafka напрямую.
Он наполняет имитатор C01, загружает три CSV, публикует оценку, создаёт агрегированный прогноз,
строит план и создаёт демонстрационную заявку. Выбор варианта и подтверждение передачи остаются за пользователем.

Для источников плана нужен норматив каждой активной клиники и вида компонента. Демо-пользователи операторов
есть только у двух клиник, поэтому отдельная операция `SEED_DEMO` доступна только `IT_SERVICE`.
`POST /dev/seed-norms` разрешён исключительно при `BS_ENV=local`, `ci` или `demo`, в остальных средах — 404.
Он добавляет только отсутствующие нормативы, из фиксированного синтетического годового расхода 36000 мл;
имеющиеся записи не меняет. Каждый норматив и его событие с аудитом фиксируются обычным сценарием inventory.
Частично завершённое наполнение можно повторить: сохранённые нормативы пропускаются.

Обычная операция ввода годового расхода и её ограничение клиникой остаются прежними. Демонстрационные
пароли задаются окружением утилиты; ответы, токены и номер случая в вывод утилиты не попадают.
Существующие принятые CSV определяются по контрольной сумме, опубликованная оценка — по версиям входов,
план и заявка — по ключам идемпотентности. Утилита не удаляет пользовательские записи.
