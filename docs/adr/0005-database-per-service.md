# ADR-0005. База и роль на сервис в одном экземпляре PostgreSQL

Статус: принят, 20.10.2026 (перенос ADR-006 прототипа).

## Контекст

Данные каждого контекста должны быть недоступны другим сервисам физически, а не дисциплиной. При этом отдельный экземпляр
PostgreSQL на сервис для пет-проекта избыточен.

## Решение

Один экземпляр PostgreSQL 16 (CloudNativePG в k8s, контейнер в compose), на каждый сервис — своя база и своя роль-владелец;
`REVOKE CONNECT ON DATABASE … FROM PUBLIC`. Межбазовых внешних ключей нет. `audit` дополнительно получает роль только с INSERT.
PITR и реплика настраиваются на уровне экземпляра и покрывают все базы одной точкой восстановления.

## Последствия

- Чужие таблицы невозможно прочитать даже по ошибке; правило владельца проверяется правами СУБД.
- Восстановление всех баз к одной точке времени согласовано (упрощает учение восстановления).
- Общая точка отказа — экземпляр; закрывается репликой CloudNativePG (NFR005–NFR007).

## Условия пересмотра

Выделение `matching` (K1) в отдельный экземпляр с шифрованием на диске при требованиях заказчика к K1.
