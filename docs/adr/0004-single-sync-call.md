# ADR-0004. Единственный синхронный межсервисный вызов: статус единиц

Статус: принят, 20.10.2026 (перенос ADR-004 Java-прототипа). Изменено [ADR-0027](0027-stage1-deviations.md), 23.10.2026:
экстренное задание при недоступном АИСТ-М не подтверждается по копии, а получает отказ `SourceSystemUnavailable` и эскалацию.

## Контекст

FR048 требует перед закреплением повторно проверить единицы по копии запаса **и** точечным запросом статуса в C01.
Оператор должен получить ответ в том же запросе («закреплено, готовьте» или причина отказа). Копия может отставать до 5 минут.

## Решение

`transfer` вызывает `inventory` синхронно `GET /internal/units/status?ids=…` (а `inventory` — C01) **до** транзакции
подтверждения и до любой блокировки. Таймаут 3 с, предохранитель (circuit breaker), сервисный токен.
Это единственный синхронный вызов между сервисами. При недоступности — `SourceSystemUnavailable`: плановое задание
остаётся `PENDING` («повторите»), экстренное — эскалация дежурному; вслепую не закрепляем.

Под блокировкой Остатка копия перепроверяется ещё раз: выдача могла прийти событием, пока шёл вызов.

## Последствия

- Нет хранимого состояния «проверяется»; нет saga-шага ожидания ответа.
- `inventory` обязан отдавать статус из своей копии, если C01 не отвечает, с пометкой `source: copy` — решение о
  принятии такого ответа принимает `transfer` по срочности (только для экстренных, с алертом).
- Все остальные взаимодействия — события и команды.
