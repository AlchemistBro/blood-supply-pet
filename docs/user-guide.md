# Руководство пользователя

Для кого: операторы клиник, врачи, аналитик, дежурный, ИТ-служба и тот, кто показывает систему.
Данные, нормативы и правила подбора синтетические. Система не принимает клинических решений: она показывает
варианты и объясняет их, выбор всегда за врачом.

Руководство составлено по коду и контрактам. Живой проход по экранам на работающем стенде 25.10.2026 не выполнен
(у Docker Desktop была нарушена сеть между контейнерами), поэтому тексты экранов могут отличаться в мелочах.
Сценарий показа с таймингом — [demo.md](demo.md).

## 1. Запуск стенда

Нужны Docker Desktop, Go 1.27.3+ и Task. Из корня репозитория, в Git Bash:

```bash
task up      # создаёт deploy/compose/.env из примера и поднимает платформу и сервисы
task seed    # наполняет демо-данными; успех — сообщение «Демо подготовлено» с plan_id и request_id
```

Не используйте `task down` как обычную остановку: он удаляет тома (данные пропадут). Остановка без потери данных:

```bash
docker compose -f deploy/compose/compose.yaml --env-file deploy/compose/.env --profile services stop
```

| Адрес | Что это |
| --- | --- |
| `https://localhost` | Приложение (самоподписанный сертификат: браузер попросит подтвердить) |
| `http://localhost:8180` | Keycloak (страница ввода пароля) |
| `http://localhost:8025` | Mailpit — письма системы |
| `http://localhost:3000` | Grafana (дашборды и алерты) |

Проверка, что всё поднялось: `https://localhost/login` открывается, а `http://localhost:8080/readyz` отвечает
`"ready":true`. Если `ready:false` и в ошибке «no route to host» — см. раздел 6.

## 2. Вход

Откройте `https://localhost`. Нажмите «Войти» или выберите готового пользователя в блоке «Демо-доступ».
Откроется страница Keycloak: введите логин и пароль `demo`. Разные роли открывайте в разных профилях браузера:
вкладки одного профиля делят одну сессию.

| Логин | Роль | Клиника | Для чего |
| --- | --- | --- | --- |
| `operator-c001` | Оператор | C001 | Запас, подтверждение и отправка передачи из своей клиники |
| `operator-c002` | Оператор | C002 | Приёмка поставки в своей клинике |
| `physician1` | Врач | C002 | Заявка на компонент, выбор варианта |
| `analyst1` | Аналитик | вся территория | Загрузка CSV, оценка потребности, планы |
| `duty1` | Дежурный | все клиники | Все задания, эскалации, ручная перевозка |
| `it1` | ИТ-служба | все (в рамках роли) | Аудит, интеграции, правила подбора |

В шапке каждого экрана видны ваша роль, клиника и время последнего обновления запаса из АИСТ-М. Если запас давно
не обновлялся, показывается предупреждение. Выход — кнопка «Выйти» (только через форму, не по ссылке).

## 3. Что делает каждая роль

Меню слева строится по роли; чего нет в меню, того роль делать не может (прямой адрес даст «403»).

### Аналитик (`analyst1`)

1. **Потребность территории** (`/demand`). Загрузите три CSV: профиль районов, историю расхода, доли «район → клиника».
   Образцы формата — ссылки на экране (шаблоны). Файл с теми же байтами второй раз не принимается: это нормально, форма
   остаётся, ничего не дублируется. Построчные ошибки показываются списком; допустимые строки сохраняются.
2. Расчёт. Выберите профиль, версию долей, историю расхода и период, нажмите «Рассчитать оценку». Если не хватает
   входного файла, экран перечислит, какого именно. Затем «Подтвердить и опубликовать» (или «Отклонить версию») оценку.
3. **План пополнения** (`/plans`). Построенный план: целевой запас клиник, защищённый запас источников, предложения
   передач и непокрытый дефицит с причинами. Дефицит — допустимый результат: система не нарушает защищённый остаток.
4. **Дефициты** (`/deficits`) и прогнозы ЧС (`/forecasts/{id}`).

### Врач (`physician1`)

1. **Заявки** (`/requests`) → «Новая заявка»: вид компонента, группа и резус, количество, срочность, ограничения.
   Номер случая пациента вводится в заявке; в системе он хранится только в зашифрованном виде.
2. Откройте заявку: список вариантов — источник, правило подбора и его версия, объяснение, время получения.
   Местный вариант (своя клиника C002) перевозки не создаёт. Для передачи из другой клиники выберите удалённый вариант
   и нажмите «Выбрать» — создаётся задание источнику.
3. Номер случая показывается только по отдельной ссылке «Показать номер случая с записью в аудит» в вашей заявке; каждое чтение
   записывается в аудит. Заявку можно отменить, пока она не исполнена.

### Оператор клиники (`operator-c001`, `operator-c002`)

1. **Запас клиники** (`/stock`): сводка по видам и группам, список единиц по FEFO (раньше истекающие первыми).
   Единицы на карантине и выбывшие не отображаются как доступные. Кнопка «Обновить из АИСТ-М» запускает синхронизацию;
   результат показывается на экране. Годовой расход и норматив вносятся на том же экране.
2. **Задания на передачу** (`/tasks`) — задания, где ваша клиника источник (или получатель). Откройте задание:
   - *Подтвердить* — выберите единицы из предложенных (FEFO). Можно подтвердить часть, если согласны на частичную
     передачу. Повторное нажатие не создаёт второго задания.
   - *Заменить единицу* — равноценной единицей по спецификации заявки (после подтверждения, до отправки).
   - *Отказать* — с причиной.
   - После статуса «Перевозка запрошена» — *Зарегистрировать отправку* (код работника, температура, контейнер).
   - Получатель (`operator-c002`) — *Зарегистрировать приёмку*: температура, целостность, при нарушении — отметка.
3. Статус задания обновляется на экране сам (SSE). Если не обновился — перезагрузите страницу.

Статусы: `PENDING` (ждёт подтверждения) → `CONFIRMED` → `TRANSPORT_REQUESTED` → `DISPATCHED` → `DELIVERED`.
Также `REJECTED`, `EXPIRED` (срок истёк — задание уходит следующему источнику), `CANCELLED`, `BROKEN`
(закреплённая единица выбыла или ушла на карантин).

### Дежурный (`duty1`)

- **Все задания** и **Эскалации** (`/duty/tasks`, `/duty/escalations`): задания любых клиник, причины эскалаций
  (источник не ответил, перевозчик отказал, исход неизвестен, нарушение температуры).
- Может подтвердить, отправить и принять передачу вместо оператора. «Назначить перевозку вручную» — когда заказ
  у перевозчика не создался. Закрытие эскалации с результатом не снимает запрет использования компонентов,
  если зафиксировано нарушение условий перевозки.

### ИТ-служба (`it1`)

- **Журнал аудита** (`/audit`): действия пользователей и системы, проверка целостности цепочки хешей («Проверить»),
  выгрузка в CSV (сама пишется в аудит).
- **Состояние интеграций** (`/integrations`): АИСТ-М, перевозчик, почта; заказы в состояниях UNKNOWN/FAILED.
- **Правила подбора** (`/rules`): версии демо-правил, добавление новой версии. Содержимое — синтетическое.

## 4. Типовой сценарий «от заявки до приёмки» (5 минут)

1. `analyst1`: `/demand` — убедиться, что входные CSV приняты и оценка опубликована; `/plans` — открыть план.
2. `physician1`: `/requests/new` — заявка RBC, например O+, 1 единица, срочно. Открыть заявку, выбрать
   **удалённый** вариант с источником C001.
3. `operator-c001`: `/tasks` — открыть новое задание, выбрать единицу из списка, «Подтвердить передачу».
   Статус станет `CONFIRMED`, затем `TRANSPORT_REQUESTED` (заказ у перевозчика; не мгновенно).
4. Тот же оператор: «Зарегистрировать отправку» (код `DEMO-COURIER`, 4 °C, целый контейнер) → `DISPATCHED`.
   В Mailpit (`localhost:8025`) появилось письмо оператору источника.
5. `operator-c002`: открыть то же задание, «Зарегистрировать приёмку» (4 °C, целый контейнер) → `DELIVERED`.
6. `it1`: `/audit` — видны все шаги; «Проверить» цепочку; `/integrations` — состояние интеграций.

Дополнительно: при приёмке отметьте «Зафиксирован выход температуры за режим в пути» — появится эскалация
у `duty1`, а компоненты будут помечены запретом использования.

## 5. Если что-то не так

| Что видите | Что значит и что делать |
| --- | --- |
| «403» | Действие не по роли или чужая клиника. Это штатный отказ; проверьте, под кем вошли |
| «Форма устарела» | Сессия обновилась. Обновите страницу и повторите действие |
| Пароль принят, но «Вход невозможен» | Старый realm Keycloak. См. [runbook](runbooks/keycloak-login.md) |
| Нет вариантов в заявке | Нет свободных единиц выше защищённого остатка или ограничения слишком строгие. Это дефицит, а не ошибка |
| Подтверждение «АИСТ-М не ответила» | Источник данных недоступен, подтверждение по копии запрещено. Повторите позже; для экстренных заданий уходит эскалация |
| Задание застряло в `CONFIRMED` | Перевозчик не ответил. Не нажимайте «Подтвердить» снова; см. [шлюз](runbooks/gateway-unknown-failed.md) |
| Сообщения не доходят | [Очередь недоставленных](runbooks/dlt-messages.md) |
| Страница входа не открывается, `readyz` = `false` | Раздел 6 |

## 6. Если стенд не отвечает

Проверка: `curl -s http://localhost:8080/readyz`. Ответ с `no route to host` до адреса `172.20.0.x` означает, что
контейнеры потеряли сетевую связность между собой (так было 25.10.2026 после зависания сети Docker Desktop):
порты на хосте открыты, но `web` не видит PostgreSQL, Kafka и Keycloak, вход невозможен.

1. Не запускайте `task down`: данные лежат в томах.
2. Перезапустите Docker Desktop (при необходимости — полностью, вместе с WSL), дождитесь «Engine running».
3. `task up` (команда идемпотентна и тома сохраняет). Проверьте `readyz` у `web`, `inventory`, `transfer`.
4. Повторный `task seed` безопасен: он пропускает уже созданное.

## 7. Что система не делает

Не заменяет решение врача и не проверяет индивидуальную совместимость; не ведёт учёт доноров и донаций (это АИСТ-М);
не формирует юридически значимый акт передачи (нужна электронная подпись сторон — организационная мера заказчика).
Подробности — [ADR-0024](adr/0024-regulatory-boundaries.md) и [реестр](compliance/register.md).
