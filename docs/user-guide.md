# Руководство пользователя

Для кого: оператор клиники, врач, аналитик, дежурный, ИТ-служба и тот, кто показывает систему.
Данные, нормативы и правила подбора синтетические. Система не принимает клинических решений: она показывает
варианты и объясняет их, выбор всегда за врачом.

Руководство проверено 25.10.2026 на работающем стенде: настоящий вход всех шести пользователей через Keycloak
и полный путь «заявка → выбор → подтверждение → заказ перевозки → отправка → приёмка». Проход выполнялся HTTP-клиентом
(формы, куки, права), без визуальной проверки в браузере, поэтому вёрстка и подсказки на экране могут отличаться
в мелочах. Сценарий показа с таймингом — [demo.md](demo.md).

## 1. Запуск стенда

Нужны Docker Desktop, Go 1.27.3+ и Task. Из корня репозитория, в Git Bash:

```bash
task up      # создаёт deploy/compose/.env из примера и поднимает платформу и сервисы
task seed    # наполняет демо-данными; успех — «Демо подготовлено» с plan_id и request_id
```

Не используйте `task down` как обычную остановку: он удаляет тома. Остановка без потери данных:

```bash
docker compose -f deploy/compose/compose.yaml --env-file deploy/compose/.env --profile services stop
```

| Адрес | Что это |
| --- | --- |
| `https://localhost` | Приложение (самоподписанный сертификат: браузер попросит подтвердить) |
| `http://localhost:8180` | Keycloak (страница ввода пароля) |
| `http://localhost:8025` | Mailpit — письма системы |
| `http://localhost:3000` | Grafana (дашборды и алерты) |

Готовность: `curl -s http://localhost:8080/readyz` должен вернуть `"ready":true`.

## 2. Вход (для всех)

1. Откройте `https://localhost`, нажмите «Войти» или выберите пользователя в блоке «Демо-доступ».
2. На странице Keycloak введите логин и пароль `demo`.
3. Разные роли открывайте в разных профилях браузера: вкладки одного профиля делят одну сессию.
4. Не входите многократно подряд (больше десятка попыток за несколько секунд): nginx ограничивает `/auth/` двумя
   запросами в секунду, лишние получат «503». Подождите несколько секунд.

В шапке видны роль, клиника, логин и время обновления запаса. Выход — кнопка «Выйти».

| Логин | Роль | Клиника |
| --- | --- | --- |
| `physician1` | Врач | C002 (№ 2) |
| `operator-c001` | Оператор | C001 (№ 1) |
| `operator-c002` | Оператор | C002 (№ 2) |
| `analyst1` | Территориальный аналитик | вся территория |
| `duty1` | Дежурный смены | все клиники |
| `it1` | Внешняя ИТ-служба | все клиники в рамках роли |

Если нужное действие в меню отсутствует или открывается «Недостаточно прав», это штатно: права зависят от роли.

## 3. Инструкции по ролям

### 3.1 Врач (`physician1`)

Меню: «Заявки врача», «Правила подбора», «Запас клиники».

1. **Новая заявка:** `Заявки врача` → «Новая заявка». Укажите вид компонента, группу и резус, количество,
   срочность, ограничения и номер случая пациента. Номер хранится зашифрованным и в списках не показывается.
2. **Варианты:** откройте заявку. Система показывает до 100 вариантов, по каждому: клиника-источник, сколько
   доступно и предложено, время получения, правило подбора с версией и объяснение «почему допустим» и «почему такой
   ранг». Местный вариант (ваша клиника № 2) перевозки не создаёт.
3. **Выбор:** у выбранного варианта нажмите «Выбрать вариант». Создаётся задание клинике-источнику; повторное нажатие
   новое задание не создаёт. Надпись «Сведений о защищённом остатке пока нет» не блокирует выбор, но означает, что
   источник может отказать на подтверждении из-за защищённого остатка.
4. **Номер случая:** в своей заявке нажмите «Показать номер случая с записью в аудит». Каждое чтение записывается в журнал.
   Видеть номер может только врач-автор заявки; все остальные роли получают отказ.
5. **Отмена:** в карточке заявки есть кнопка отмены, пока заявка не исполнена.

### 3.2 Оператор клиники-источника (`operator-c001`)

Меню: «Задания на передачу», «План пополнения», «Запас клиники».

1. **Запас** (`/stock`): сводка по видам и группам (единицы, объём, ближайший срок), список «Единицы по сроку
   годности (FEFO)»: раньше истекающие первыми. Карантин и выбывшие единицы в доступных не показываются.
   «Обновить из АИСТ-М» запускает синхронизацию и показывает результат. Годовой расход и норматив вносятся на экране запаса.
2. **Задания** (`/tasks`): выберите клинику-источник и статус, нажмите «Показать». Откройте задание из списка.
3. **Подтвердить передачу:** отметьте единицы (не больше, чем запрошено, и не больше 10), нажмите «Подтвердить передачу».
   - Ничего не отмечено → «Не выбраны единицы».
   - Больше, чем в заявке → «запрос не подходит к заданию».
   - Повтор той же формы безопасен: задание не удвоится.
4. **Заменить единицу** (после подтверждения, до отправки) или **Отказать** (с причиной) — отдельные формы в карточке.
5. Через 1–2 секунды статус меняется на «Перевозка запрошена» (заказ принят перевозчиком). Обновите страницу, если
   статус не сменился сам.
6. **Зарегистрировать отправку:** «Код уполномоченного работника» (латиница без пробелов, например `DEMO-COURIER`;
   ФИО система отклонит), «Температура при отправке, °C» (число), время UTC (пусто — текущее), отметка
   «Целостность контейнера проверена». **Без отметки целостности отправка отклоняется.** Нажмите «Подтвердить отправку».

Если у задания источник — клиника, у которой нет своего оператора (например, № 73), подтверждать и отправлять должен
дежурный (3.5): оператор чужой клиники получает отказ.

### 3.3 Оператор клиники-получателя (`operator-c002`)

1. Откройте задание из списка («Задания на передачу», клиника-получатель) или по ссылке от врача.
2. Когда статус «Отправлено» (`DISPATCHED`), в карточке появится форма **«Зарегистрировать приёмку»**: температура при
   прибытии, время UTC (пусто — текущее), «Целостность контейнера сохранена».
3. Отметка **«Зафиксирован выход температуры за режим в пути»** ставится только при реальном нарушении: задание
   получает признак запрета использования и создаётся эскалация для дежурного (ПП РФ № 641, п. 98).
4. Принять поставку может только оператор получателя или дежурный; оператор другой клиники получает отказ.
   Повторная приёмка безопасна и ничего не меняет.
5. Статус становится «Доставлено» (`DELIVERED`).

### 3.4 Аналитик (`analyst1`)

Меню: «Потребность территории», «План пополнения».

1. **Загрузка** (`/demand`): выберите вид («Профиль районов», «История расхода», «Доли район → клиника»), файл CSV
   до 5 МиБ, «Загрузить и проверить». Образцы — ссылки «Демо-шаблоны» на экране.
   - Принимается, если формат верный; построчные ошибки показываются списком, допустимые строки сохраняются.
   - Файл с теми же байтами второй раз не принимается: страница сообщает, что он уже сохранён, форма остаётся.
   - История расхода за уже загруженные периоды отклоняется как пересечение (если по ней уже есть оценка).
2. **Расчёт:** «Рассчитать новую версию»: выберите профиль, версию долей, историю расхода и период. Если не хватает
   файла, экран перечислит, какого именно. Затем «Подтвердить и опубликовать» (или «Отклонить версию»).
3. **План** (`/plans`): целевой запас клиник, защищённый запас источников, предложенные передачи и непокрытый дефицит
   с причинами. Дефицит допустим: система не нарушает защищённый остаток. «Реестр дефицита» — `/deficits`.
   Прогнозы ЧС приходят от C02 автоматически (имитатор отправляет их в planning).
4. Запаса клиник аналитик не видит (нет права «Запас»), в шапке для него может быть «Время обновления запаса неизвестно»
   — это нормально.

### 3.5 Дежурный (`duty1`)

Меню: «Задания на передачу», «Потребность территории», «План пополнения», «Заявки врача», «Эскалации», «Все задания»,
«Запас клиники», «Журнал аудита», «Состояние интеграций».

1. **Все задания** (`/duty/tasks`): задания всех клиник с фильтром по статусу и признаком «Запрет использования».
2. Может **подтвердить, заменить, отказать, отправить и принять** передачу любой клиники — вместо оператора. Это
   нужно, когда у источника нет своего оператора или он не отвечает. Все такие действия пишутся в аудит.
3. **Эскалации** (`/duty/escalations`): причина (источник не ответил, перевозчик отказал, исход неизвестен, нарушение
   температуры) и кнопка закрытия с результатом. **Закрытие эскалации не снимает запрет использования**, если зафиксировано
   нарушение условий перевозки. «Назначить перевозку вручную» — когда заказ у перевозчика не создался.
4. Заявки врача дежурный видит, но не создаёт и не выбирает варианты; номер случая ему недоступен.

### 3.6 ИТ-служба (`it1`)

Меню: «Правила подбора», «Запас клиники», «Журнал аудита», «Состояние интеграций».

1. **Журнал аудита** (`/audit`): фильтры по модулю, действию, объекту, пользователю и периоду; «Скачать страницу CSV»
   (до 100 записей; сама выгрузка пишется в аудит). Кнопка **«Проверить цепочку хешей»** показывает «Цепочка цела» и число
   проверенных записей; при разрыве называет номер записи.
2. **Состояние интеграций** (`/integrations`): АИСТ-М (водяной знак, последний сеанс), заказы перевозчика с состояниями
   (`ACCEPTED`, `UNKNOWN`, `FAILED`), журнал доставки писем, очередь недоставленных сообщений.
3. **Правила подбора** (`/rules`): версии демо-правил, добавление новой версии. Содержимое синтетическое.
4. Письма системы — в Mailpit (`http://localhost:8025`). Если приходят письма `SECURITY_INCIDENT`, сработал детектор
   подозрительных действий (например, серия отказов в доступе): разбор — [runbook](runbooks/pd-incident-24h-72h.md).

## 4. Типовой сценарий «от заявки до приёмки» (проверен)

1. `physician1`: заявка → удалённый вариант → «Выбрать вариант».
2. Источник без оператора → `duty1` (иначе `operator-c001`, если источник C001): `/duty/tasks` → задание → единица → «Подтвердить передачу».
3. Через 1–2 с «Перевозка запрошена»; в Mailpit письмо `URGENT_TASK`.
4. Тот же пользователь: «Зарегистрировать отправку» (`DEMO-COURIER`, 4 °C, целостность отмечена) → «Отправлено».
5. `operator-c002`: «Зарегистрировать приёмку» (4 °C, целостность) → «Доставлено».
6. `it1`: `/audit` → «Проверить цепочку хешей» → «Цепочка цела»; `/integrations` — заказ `ACCEPTED`.

## 5. Если что-то не так

| Что видите | Что делать |
| --- | --- |
| «403 / Недостаточно прав» | Штатный отказ: действие не по роли или чужая клиника |
| «Форма устарела» | Обновите страницу в том же профиле браузера и повторите действие из свежей формы |
| «503» при входе | Слишком частые попытки входа (лимит `/auth/`); подождите несколько секунд |
| «Не выбраны единицы» / «запрос не подходит к заданию» | Отметьте от одной до нужного числа единиц из списка |
| «Операция не выполнена. Проверьте код работника, целостность, температуру и время» | Код без пробелов, температура числом, **отметка целостности обязательна** |
| Нет вариантов в заявке | Нет свободных единиц выше защищённого остатка или ограничения слишком строгие: это дефицит, не ошибка |
| «АИСТ-М не ответила» | Подтверждение по копии запрещено; повторите позже, экстренному заданию уйдёт эскалация |
| Задание застряло в «Подтверждено» | Не нажимайте «Подтвердить» снова; смотрите [шлюз](runbooks/gateway-unknown-failed.md) |
| Врач не видит свою заявку | Заявка создана под другим идентификатором пользователя; см. [вход](runbooks/keycloak-login.md) |
| Вход принят, но «Вход невозможен» | Старый realm Keycloak: [runbook](runbooks/keycloak-login.md) |

## 6. Если стенд не отвечает

`curl -s http://localhost:8080/readyz`. Ответ с `no route to host` до `172.20.0.x` означает потерю связи между
контейнерами (так бывает после зависания Docker Desktop). Не запускайте `task down`: данные лежат в томах.
Перезапустите Docker Desktop (при необходимости с WSL) и выполните `task up` (команда идемпотентна), затем проверьте `readyz`.
Если Docker не стартует с ошибкой `device /dev/sdd is not usable: device or resource busy`, закройте Docker Desktop,
выполните `wsl --shutdown` и запустите его снова.

## 7. Что система не делает

Не заменяет решение врача и не проверяет индивидуальную совместимость; не ведёт учёт доноров и донаций (это АИСТ-М);
не формирует юридически значимый акт передачи (нужна электронная подпись сторон — организационная мера заказчика).
Подробности — [ADR-0024](adr/0024-regulatory-boundaries.md) и [реестр](compliance/register.md).
