# Аудит кода, 25.10.2026

Состояние: `main`, коммит `adec8d8`. Аудит выборочный: сборка и статический анализ, обычные и интеграционные тесты
на временном локальном PostgreSQL 16.15, проверка защит мутациями, чтение ключевых мест кода и конфигурации.
Стенд (compose) в момент аудита был недоступен, поэтому поведение интерфейса в браузере не проверялось.
Это не полный аудит безопасности и не заменяет сканирование образов и нагрузочные проверки.

## Сильные стороны

- Ядро саги: порядок блокировок «Остаток → обязательство», перепроверка под блокировкой, CAS-переходы, частичный
  уникальный индекс как последний рубеж, откат всей транзакции при коллизии. Защиты подтверждены мутациями.
- Номер случая пациента: шифрование на уровне приложения (AES-256-GCM, привязка к заявке), расшифровка только в
  `matching` и `inventory` (правило `archtest` транзитивное), запись в аудит и выдача номера в одной транзакции.
- Открытое перенаправление после входа закрыто белым списком маршрутов и отсевом `\`, юникода и `%`-обходов.
- Правила архитектуры соблюдены механически: нет прямого `kgo` вне `libs/messaging`, нет склейки SQL, время только
  через `Clock` в бизнес-коде, нет `panic` вне инициализации.
- Матрица прав генерируется из OpenAPI, на каждую защищённую операцию есть автоматические проверки 401/403.

## Находки

Серьёзность: **высокая** — исправить до любого использования вне личного ноутбука; **средняя** — исправить до
релиза; **низкая** — гигиена.

### Высокая

**A1. Порты compose открыты всей сети.** В `deploy/compose/compose.yaml` порты объявлены без привязки к `127.0.0.1`
(`"5433:5432"`, `"8180:8080"`, `"9092:9092"`, `"3000:3000"`, `"8101:8080"` и др.), `netstat` показывает `0.0.0.0`.
Из сети доступны PostgreSQL (`postgres/postgres`), Keycloak и Grafana с `admin/admin`, Kafka без аутентификации,
имитаторы с `/dev/*` без авторизации, `web` в обход nginx. На ноутбуке в чужой сети или VPN это прямой риск.
Исправление: `"127.0.0.1:5433:5432"` и т. д. для всех публикуемых портов (кроме, возможно, 443 по решению владельца).

**A2. Отключение авторизации не привязано к окружению.** `libs/runtime/runtime.go`: при `BS_AUTH_DISABLED=true` в любом
`BS_ENV` сервис принимает токен вида `dev:<кто-угодно>:SERVICE` без проверки. Защита держится только на соглашении
«в compose и k8s значение false». Исправление: отказывать в запуске, если `AuthDisabled` и `BS_ENV` не `local`/`ci`.

### Средняя

**B1. Проверка `aud` необязательна.** `libs/httpx/auth/verifier.go`: при пустом `BS_OIDC_AUDIENCE` проверка пропускается
(`SkipClientIDCheck`). В compose и k8s значение задано (`blood-supply-api`), но отказ по умолчанию открытый.
Исправление: пустой `aud` допустим только в `local`/`ci`, иначе ошибка конфигурации.

**B2. `/readyz` публикуется наружу и раскрывает внутреннее устройство.** Через nginx доступен `https://localhost/readyz`;
при сбое в ответе внутренние адреса (`172.20.0.7:29092`) и имена баз/ролей. Исправление: закрыть `/readyz` в nginx и
ingress (как уже закрыт `/metrics`), оставив детали только внутри сети.

**B3. Секреты по умолчанию в compose.** `postgres/postgres`, `admin/admin`, `services-demo-secret`, демо-ключи сессии и K1
лежат в `.env.example` с пометкой «демо». Для локального стенда допустимо; важно, чтобы A1 был закрыт и значения
не использовались вне стенда.

**B4. Внешний URL базы в корне.** Файл `doc_2026-10-24_19-34-51.env` (`DATABASE_URL`) исключён из git и в истории его нет,
но учётные данные ранее передавались в переписку. Рекомендация: сменить пароль той базы и удалить файл.
