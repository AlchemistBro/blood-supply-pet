## Аутентификация, роли и CSRF

Найден и исправлен разбор `clinic_id`: дробное значение раньше усекалось, а большое целое теряло точность
при преобразовании через float64. Claim теперь читается как JSON-число без округления и проверяется как
положительный int64. Проверены дробь, ноль, отрицательное значение, переполнение и подписанный JWT
с числами 9007199254740993 и 9223372036854775807. Регрессионный тест до исправления падал.

Набор `TestOpenAPIRejectsEveryUnauthorizedRole` строится из встроенного OpenAPI каждого сервиса и `policy.go`.
Покрыты все 107 защищённых операций восьми backend API и web:

- 422 проверки запрещённых ролей: 403 и ровно одна соответствующая запись ACCESS_DENIED;
- 126 проверок backend API без токена и с неверной подписью: 401;
- web использует настоящую зашифрованную cookie тестового OIDC-потока и корректный CSRF-токен;
  запрещённые запросы не доходят до HTTP-клиентов backend;
- допущенные роли и ограничения клиник проверяются бизнес-сценариями сервисов;
  генерируемый набор проверяет именно отказы.

Отрицательный контроль: в отдельной копии исходников отключена проверка права notification.
Новый тест упал на ответе 204 вместо 403. Основная рабочая копия при этом не изменялась.
Дополнительно прошли проверки токена другой сессии для POST/PUT/PATCH/DELETE и отказ CSRF-токену из query.

Существующие проверки CSP без unsafe-inline/unsafe-eval, frame-ancestors none, HSTS за TLS,
no-store, атрибутов cookie, nonce/state/PKCE, открытых перенаправлений и экранирования XSS прошли.
Это HTTP-тесты и локальные имитаторы, не проверка браузера и работающего Keycloak.
