# Рабочее окружение на Windows с VPN и Docker Desktop

Разбор от 20.10.2026. Во время разработки несколько раз обрывалась связь агента с API (ошибка `ENOTFOUND`),
падали загрузки образов (`unexpected EOF`), движок Docker останавливался сам. Ниже причины, найденные по журналам, и меры.

## Что показали журналы

| Наблюдение | Источник | Вывод |
| --- | --- | --- |
| Служба Outline: `client pipe dropped with routing active - rolling back` в 04:30 и 07:29 | журнал Windows, источник OutlineService | Клиент Outline потерял связь со службой; служба откатывает маршруты |
| Сразу после этого `stopped smartdnsblock`, `removed leaky-DNS firewall rules`, затем повторный запуск | там же | Блокировка DNS вне туннеля снимается и ставится заново. Десять-двадцать секунд DNS не работает, отсюда `ENOTFOUND` |
| Оба обрыва Outline случились, когда движок Docker был остановлен или ещё не использовался | сопоставление с журналом Docker | Docker не единственная причина обрыва VPN |
| `Netwtw14` 6062 и «ограниченные возможности подключения» | журнал Windows | Драйвер Wi-Fi Intel AX211 периодически сбрасывает адаптер |
| `idle mode activated ... VM stopped` | журнал Docker `monitor.log` | Docker Desktop сам выключает движок по простою (Resource Saver) |
| Каждый запуск и остановка движка создают и удаляют адаптер `WSL (Hyper-V firewall)` | журнал Hyper-V | Outline получает «network changed» на каждый такой цикл |
| `short read: expected 489128071 bytes but got 181097125: unexpected EOF` | вывод `docker compose` | Крупная загрузка оборвалась на середине слоя |

Итог: основная причина потери связи с API — срыв Outline с откатом DNS-блокировки. Docker и Wi-Fi-драйвер
добавляют события «сеть изменилась» и нагрузку на туннель, поэтому совпадение с запуском Docker не случайно.

## Что сделать один раз

1. **Docker Desktop → Settings → Resources → Resource Saver: выключить.** Движок перестанет засыпать и пересоздавать адаптер.
2. **Docker Desktop → Settings → Docker Engine**: ограничить параллельные загрузки и задать DNS.
   ```json
   {
     "max-concurrent-downloads": 1,
     "dns": ["1.1.1.1", "9.9.9.9"]
   }
   ```
   Если обрывы загрузок повторятся, добавить `"mtu": 1400`.
3. **Outline**: обновить клиент до последней версии. Не закрывать его окно во время работы.
4. **Драйвер Wi-Fi Intel AX211**: обновить; в свойствах адаптера снять «Разрешить отключение этого устройства для экономии энергии».
5. Держать включённым **один** VPN. Два клиента спорят за маршруты и правила DNS.
6. По желанию включить зеркальную сеть WSL, она лучше уживается с VPN. Файл `C:\Users\<пользователь>\.wslconfig`:
   ```ini
   [wsl2]
   networkingMode=mirrored
   dnsTunneling=true
   autoProxy=true
   ```
   После изменения: `wsl --shutdown`.

## Перед сессией разработки

1. Запустить Docker Desktop и дождаться статуса Running. Не перезапускать его во время работы.
2. Один раз скачать тяжёлые образы вне рабочей сессии: `bash scripts/pull-images.sh`. Скрипт повторяет попытки и качает по одному.
3. Проверить, что стенд поднимается: `task up`. Остановка: `task down`.

## Если связь всё же оборвалась

- Файлы проекта лежат на диске, работа не теряется. Коммиты делаются после каждого проверенного блока, поэтому
  потерянным может оказаться только последний незафиксированный шаг.
- Прерванную загрузку образа можно просто повторить: уже скачанные слои Docker не качает заново.
- Проверить DNS: `nslookup github.com`. Если не отвечает, подождать, пока Outline завершит `resetRouting` (около двадцати секунд).
