# Восстановление PostgreSQL

Основание: ADR-0009 и ADR-0035. Для встроенного Barman API ветки CNPG 1.27 используется
[bootstrap recovery в новый кластер](https://cloudnative-pg.io/docs/1.27/recovery/).
Имеющийся `barmanObjectStore` устаревает; переход на плагин требует отдельной проверки совместимости архива.

Учение: `task k8s:drill`, только из Git Bash в подготовленном kind `blood-supply` с overlay local/ci.
Сценарий требует два экземпляра исходного PostgreSQL, создаёт таблицу маркеров в служебной базе postgres,
ждёт завершённую базовую копию, сохраняет точку между двумя маркерами и проверяет архивирование WAL.
После этого удаляется только pod текущего primary, а PITR создаёт отдельный `pg-drill`.

Исходные PVC, архив и базы сервисов не удаляются. Кластер `pg-drill` сохраняется для проверки результата;
повторный запуск при его наличии прекращается, не перезаписывая восстановленную копию.
Отчёт `docs/perf/drill-<время>.md` появляется только при фактическом успешном выполнении.
RTO измеряется до проверки маркеров и готовности исходного кластера; выбранное окно PITR не является
универсальной гарантией RPO. Полный прикладной smoke против восстановленной копии выполняется отдельно.

Для реального восстановления: остановить записи приложения, проверить доступность и целостность архива,
выбрать целевую точку, создать новый Cluster, проверить маркеры и прикладные данные, затем сменить адрес БД
и постепенно вернуть сервисы. Старый кластер сохранять до приёмки восстановления. Не применять учебный
сценарий к рабочему кластеру; его контекст и метки специально ограничены.
