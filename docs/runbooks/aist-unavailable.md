# АИСТ-М недоступна

АИСТ-М (C01) — учётная система единиц компонентов крови. Система читает её копию (ИНТ-01, `inventory`) и делает
один синхронный вызов: перед подтверждением передачи `transfer` проверяет статус выбранных единиц через `inventory`
(ADR-0004, таймаут 3 с, предохранитель `inventoryclient`).

## Что видит пользователь

| Где | Что |
| --- | --- |
| Подтверждение передачи | «АИСТ-М не ответила. Задание остаётся в ожидании, повторите через минуту.» (`SourceSystemUnavailable`) |
| Шапка любого экрана | Жёлтая полоса «Данные запаса устарели (обновлено … назад)» при превышении порога NFR015 |
| Полоса под шапкой | Красная «АИСТ-М недоступна: подтверждение временно невозможно» (этап 2) |

Обязательства на передачу при этом не теряются: они остаются `PENDING` до подтверждения или срока; по сроку —
`EXPIRED` и эскалация к следующему источнику. Закреплений без проверки в АИСТ-М нет.

## Сигналы

Алерт `bs-inventory-breaker-open` (вызовы `transfer → inventory` с исходом `circuit_open`); дашборд
«АС: исходящие HTTP-вызовы», «АС: сага подтверждения передачи» (панель «Вызовы inventory из transfer»);
водяной знак запаса в шапке.

## Действия

1. Различите, где разрыв:
   - `inventory` не отвечает `transfer` (исходы `timeout`/`error` у клиента `inventory`, `/readyz` inventory) —
     это внутренняя проблема, а не АИСТ-М;
   - `inventory` жив, но не достаёт АИСТ-М (ошибки синхронизации ИНТ-01 в журнале `inventory`, растёт возраст
     водяного знака) — недоступна АИСТ-М.
2. В демо АИСТ-М — имитатор `sim-aist`: проверьте его пульт сбоев и `/healthz`.
3. Сообщите операторам клиник-источников: подтверждения временно невозможны, повторять через несколько минут;
   задания не пропадут.
4. Экстренные заявки: подтверждение по копии без проверки в АИСТ-М выключено (`BS_ALLOW_COPY_CONFIRM_EMERGENCY=false`,
   ADR-0027). Не включайте флаг без решения ответственного лица: риск закрепить уже выданную единицу. Дежурный смены
   решает вопрос вне системы по регламенту клиники.
5. После восстановления: предохранитель замкнётся сам (по умолчанию через 10 с полуоткрытого состояния), водяной знак
   обновится после очередной синхронизации; для срочного обновления — «Обновить из АИСТ-М» на экране запаса (FR050, этап 3).
6. Если недоступность длилась дольше порога NFR015 — проверьте задания, ушедшие в `EXPIRED` за это время: эскалации
   должны были открыть обязательства у следующих источников.
