# Экраны по ролям

Маршруты `web`. Все экраны показывают шапку с водяным знаком (NFR015). Данные берутся из сервисов по HTTP с JWT пользователя.

## Общие

| Маршрут | Экран | Источник данных |
| --- | --- | --- |
| `/login` | Вход: кнопка «Войти через единую учётную запись» (Keycloak) и блок «Демо-доступ» с четырьмя ролями | Keycloak |
| `/` | Переход на стартовый экран роли | — |
| `/forbidden` | «Недостаточно прав» | — |
| `/dev` (профиль dev) | Dev-панель: имитаторы (создать единицу, выдать единицу, сбои C01/C03, отправить прогноз), ссылки Mailpit, Kafka UI, Grafana, «Загрузить демо-данные» | sim-*, testdata |

## Оператор клинической организации (`CLINIC_OPERATOR`)

| Маршрут | Экран | Этап |
| --- | --- | --- |
| `/operator/tasks` | Задания на передачу: таблица O07 своей клиники-источника (срочность, получатель, вид, количество, статус, срок с таймером), фильтры, live-обновление | 2 |
| `/operator/tasks/{id}` | Карточка задания: параметры, требования к единицам (без фенотипа в явном виде: «есть требования к фенотипу»), список подходящих единиц FEFO с чекбоксами, «подтвердить частично», «Подтвердить передачу», «Заменить единицу», «Отказать», история | 2 |
| `/operator/tasks/{id}/patient-case` | Показ номера случая по кнопке (аудит `READ_PATIENT_CASE`) | 6 |
| `/operator/stock` | Запас клиники: вид × группа, единиц, литров, ближайший срок, норматив, «ниже норматива»; «Обновить из АИСТ-М» | 3 |
| `/operator/units` | Единицы FEFO с фильтрами; `/operator/units/{id}` карточка с историей | 3 |
| `/operator/norms` | Годовой расход и норматив: форма ввода Kгод, расчёт, история | 3 |
| `/operator/plan` | План пополнения: что получит клиника и что отдаёт, статусы, покрытие; объяснение источника | 5 |
| `/operator/forecasts` | Прогнозы ЧС: строки, «грубая оценка», коррекция строки с причиной | 5 |

## Врач-трансфузиолог (`PHYSICIAN`)

| Маршрут | Экран | Этап |
| --- | --- | --- |
| `/physician/requests` | Мои заявки: статус, задание (live), дефицит с причиной, «Отменить» | 6 |
| `/physician/requests/new` | Новая заявка: номер случая, вид, количество, срочность, группа и резус, фенотип, ограничения | 6 |
| `/physician/requests/{id}` | Заявка: параметры, варианты по рангу с объяснением, «Выбрать»; после выбора — статус задания и перевозки | 6 |
| `/physician/requests/{id}/patient-case` | Показ номера случая по кнопке (аудит) | 6 |

## Территориальный аналитик (`TERRITORIAL_ANALYST`)

| Маршрут | Экран | Этап |
| --- | --- | --- |
| `/analyst/files` | Загрузка CSV: вид файла, drag-and-drop, результат проверки, отклонённые строки, шаблоны | 4 |
| `/analyst/history` | История расхода | 4 |
| `/analyst/shares` | Доли район → клиника, версии с основанием | 4 |
| `/analyst/estimates` | Версии оценки: рассчитать, просмотр строк, входы, «Подтвердить публикацию» / «Отклонить» | 4 |
| `/analyst/plan` | План пополнения (просмотр) и реестр дефицита | 5 |

## Дежурный смены (`DUTY_OFFICER`)

| Маршрут | Экран | Этап |
| --- | --- | --- |
| `/duty/escalations` | Эскалации: не подтверждено в срок, C03 молчит/отказал, АИСТ-М недоступна при экстренной; «Назначить перевозку вручную», «Закрыть с комментарием» | 7 |
| `/duty/tasks` | Все задания по всем клиникам | 2 (расширение) |
| `/duty/stock` | Запас всех клиник, сводка «ниже норматива» | 3 |
| `/duty/deficits` | Реестр дефицита | 5 |

## Внешняя ИТ-служба (`IT_SERVICE`)

| Маршрут | Экран | Этап |
| --- | --- | --- |
| `/it/audit` | Журнал аудита с фильтрами, проверка цепочки, экспорт CSV | 7 |
| `/it/rules` | Правила подбора O15: версии, основание, срок действия; добавить версию | 6 |
