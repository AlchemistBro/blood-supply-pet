# Форматы CSV территориального аналитика

Контракт файлов, которые аналитик загружает в `demand` (FR016, FR017, FR045, FR046). Разбор и проверка —
`services/demand/internal/domain`. Изменение формата — правка этого документа, тестов домена и шаблонов вместе.

Данные в примерах синтетические (ADR-0010): коды районов и клиник — из `libs/refdata`, доли и объёмы демонстрационные.

## Общие правила

| Правило | Значение |
| --- | --- |
| Кодировка | UTF-8. Метка BOM в начале файла допускается и отбрасывается (её пишет Excel). Файл не в UTF-8 отклоняется целиком |
| Разделитель полей | точка с запятой `;` |
| Кавычки | по RFC 4180: поле с `;` или кавычкой берётся в двойные кавычки, кавычка внутри удваивается |
| Первая строка | заголовок с именами колонок. Порядок колонок любой, имена — точно как в таблицах ниже |
| Лишние колонки | файл отклоняется целиком: в системе нет полей для ПДн, неизвестные данные не принимаются |
| Пустые строки | пропускаются |
| Пробелы | по краям значений и имён колонок отбрасываются |
| Дата | `ГГГГ-ММ-ДД`, например `2026-01-01`. Период включает обе границы, `period_end ≥ period_start` |
| Доля | десятичная дробь от 0 до 1, разделитель дробной части — точка или запятая (`0.35` и `0,35`). Округляется до 4 знаков (как `numeric(5,4)` в ПР6), половина — от нуля |
| Объём | целое число миллилитров |
| Длина текста | `data_source` и `basis` — не длиннее 256 символов |
| Номер строки в ошибке | номер строки файла, заголовок — строка 1 |

Допуск суммы долей по району: `1 ± 0,0001` (демо-допуск задачи 04). Сравнение ведётся в десятитысячных долях,
после округления каждой доли до 4 знаков: сумма от 0,9999 до 1,0001 включительно принимается.

### Итог проверки файла

| Статус | Когда |
| --- | --- |
| `ACCEPTED` | все строки приняты |
| `PARTIAL` | часть строк отклонена, хотя бы одна принята |
| `REJECTED` | файл отклонён целиком (кодировка, заголовок, нет строк данных) или не принято ни одной строки |

Отклонённая строка попадает в `file_row_error` одной записью: номер строки и причины через `; ` в виде
«поле: сообщение». Источник и период файла (`statistics_file.data_source`, `period_start`, `period_end`) — сводка по
строкам с корректными источником и периодом: разные источники через `; ` в порядке появления, период — от самого
раннего начала до самого позднего конца.

## DISTRICT_PROFILE — профиль районов (O04, FR016, FR017)

Одна строка — один район: население, доли восьми групп AB0/Rh, источник и период актуальности.

| Колонка | Обязательна | Проверка |
| --- | --- | --- |
| `district_code` | да | район из справочника; район не повторяется в файле |
| `population` | да | целое > 0, не больше 2 147 483 647 |
| `share_O+`, `share_O-`, `share_A+`, `share_A-`, `share_B+`, `share_B-`, `share_AB+`, `share_AB-` | да | доля группы от 0 до 1; сумма восьми долей = 1 ± 0,0001 |
| `data_source` | да | непустой текст |
| `period_start`, `period_end` | да | даты, конец не раньше начала |

```csv
district_code;population;share_O+;share_O-;share_A+;share_A-;share_B+;share_B-;share_AB+;share_AB-;data_source;period_start;period_end
D01;770000;0,33;0,04;0,35;0,04;0,15;0,02;0,06;0,01;ДЕМО: статистика района;2026-01-01;2026-12-31
D02;1180000;0,32;0,05;0,35;0,04;0,15;0,02;0,06;0,01;ДЕМО: статистика района;2026-01-01;2026-12-31
```

## CONSUMPTION_HISTORY — история расхода (O17, FR045)

Одна строка — расход одного вида компонента за период по всей территории. Это база `B(k, p)` расчёта (FR019).
Объём — в мл, как `consumed_volume_ml` в ПР6.

| Колонка | Обязательна | Проверка |
| --- | --- | --- |
| `component_kind_code` | да | вид из справочника |
| `period_start`, `period_end` | да | даты, конец не раньше начала; периоды одного вида в файле не пересекаются |
| `consumed_volume_ml` | да | целое ≥ 0, не больше 999 999 999 999 |
| `data_source` | да | непустой текст |

```csv
component_kind_code;period_start;period_end;consumed_volume_ml;data_source
RBC;2025-01-01;2025-12-31;36500000;ДЕМО: отчёт о расходе
CRYO;2025-01-01;2025-12-31;730000;ДЕМО: отчёт о расходе
```

## CLINIC_SHARE — доли район → клиника (O16, FR046)

Одна строка — доля потребности района `w(r, c)`, относимая к клинике. Доли — расчётная схема обслуживания, а не
закрепление жителей. Принятый файл создаёт новую версию долей; `valid_from` версии — самое раннее `period_start`.

| Колонка | Обязательна | Проверка |
| --- | --- | --- |
| `district_code` | да | район из справочника |
| `clinic_code` | да | клиника из справочника; пара район — клиника не повторяется |
| `clinic_share` | да | доля больше 0 и не больше 1 (после округления до 4 знаков) |
| `basis` | да | основание: история обслуживания, схема маршрутизации или сценарий моделирования |
| `data_source` | да | непустой текст |
| `period_start`, `period_end` | да | даты, конец не раньше начала |

Сумма долей района по принятым строкам должна быть 1 ± 0,0001. Иначе отклоняются все строки этого района с
указанием суммы: доли района принимаются целиком или никак.

```csv
district_code;clinic_code;clinic_share;basis;data_source;period_start;period_end
D01;C017;0,6;ДЕМО: схема маршрутизации;ДЕМО: решение ДЗМ;2026-01-01;2026-12-31
D01;C001;0,4;ДЕМО: схема маршрутизации;ДЕМО: решение ДЗМ;2026-01-01;2026-12-31
```

## Расчёт фоновой потребности (FR019)

Расчёт — `domain.CalculateEstimate`. Объёмы — целые мл; каждое деление объёма между частями выполняется методом
наибольших остатков, поэтому сумма частей всегда точно равна целому.

1. `B(k, p)` — средний суточный расход вида `k` по выбранным периодам истории, умноженный на число дней периода
   оценки `p`: `B = Σ consumed_volume_ml × days(p) / Σ days(history)`, округление до целого мл, половина — вверх.
   Пересекающиеся периоды истории одного вида не допускаются.
2. `V(r, k, p)` — `B(k, p)`, разделённый между районами пропорционально населению из профиля.
3. `D(r, k, g, p) = V × s(r, g)` для видов с `is_group_applicable`; для остальных видов разреза по группам нет,
   `D(r, k, p) = V`.
4. `D_c = Σ_r w(r, c) · D` — каждое `D` района делится между клиниками по долям `w(r, c)`, части суммируются по клинике.

Нормирование: доли делятся на свою сумму (допуск ±0,0001 не теряет и не добавляет мл). Равные остатки получают
лишний мл в порядке справочника (районы и клиники — по возрастанию идентификатора, группы — по порядку справочника).
