# Локальная приёмка Go и PostgreSQL, 24.10.2026

Среда: Windows amd64, Go 1.27.2, PostgreSQL 16.15. Docker, WSL, Kubernetes и деплойные тесты не запускались.
Использован отдельный кластер из установленного PostgreSQL, только на loopback и свободном порту.
Системная служба PostgreSQL не изменялась. Для каждого теста создавалась отдельная база `bs_test_<UUID>`;
по завершении баз с этим префиксом в тестовом кластере не осталось.
Созданный для приёмки сервер штатно остановлен после проверок.

## Итоговый прогон

`GOPROXY=off`, `GOFLAGS=-mod=mod`, `CGO_ENABLED=0`, `BS_TEST_NO_DOCKER=true`.
В `BS_TEST_DB_URL` задан административный URL отдельного тестового PostgreSQL.

```text
go test -count=1 -p 2 -parallel 4 -timeout 3m ./... ./libs/testdata
# exit 0: 73 пакета с тестами

go test -json -tags integration -count=1 -p 2 -parallel 2 -timeout 12m ./libs/... ./services/...
# exit 0: 72 пакета с тестами, 1258 успешных тестов/подтестов, 15 пропусков
```

Второй прогон: 20:16:27–20:19:08 МСК, около 161 с. Ещё 65 пакетов не содержат тестов.
Число 1258 включает вложенные подтесты и обычные тесты, включённые при сборке с тегом integration.
15 пропусков требуют Kafka: 4 в `libs/messaging`, 6 в приложении logistics-gateway,
5 в Kafka-адаптере transfer. Без брокера тесты явно пропускаются до запуска Testcontainers.

Прошли миграции, справочники, авторизация API, приложения inventory/demand/planning/matching/transfer,
notification и audit, PostgreSQL-адаптеры и фитнес-тесты transfer. Среди проверенных сценариев:
50 конкурентных подтверждений одной единицы, выбытие/карантин во время подтверждения,
снятие закрепления пациента с повтором после рестарта, откат пакетного сохранения оценки,
восстановление планирования без повторных команд, повтор SMTP и дедупликация инцидентов аудита.

## Исправления по результатам тестов

- `750874e`: изоляция и удаление временных баз, запрет неявного Docker, чтение URL из файла без вывода секрета.
- `50a70f9`: актуальные маршруты/права и эталоны UI; неполные события перевозки отклоняются до вызова приложения.
- `e463dc1`: явный `timestamptz` при подавлении повторных инцидентов аудита.
- `ec8bde5`: пакетная запись строк оценки demand в одной транзакции с проверкой отката.
- `95b9b13`: новое закрепление, появившееся до блокировки Остатка, обрабатывается под уже взятой блокировкой.
  Детерминированный регрессионный тест сначала воспроизвёл ошибку, затем прошёл вместе с фитнес-тестами.
  Смена области Остатков по-прежнему требует повтора с правильным набором блокировок.
  Исправлены фикстуры фенотипа transfer и чтения событий защищённого объёма inventory.
  Внешняя задержка БД учитывается только в таймаутах фикстур inventory; производственный таймаут не менялся.

На внешнем PostgreSQL из файла окружения отдельно прошли миграции, справочники, lifecycle временной базы,
весь пакет приложения audit, сохранение/публикация/откат оценки demand и API статуса единиц inventory.

Оставшиеся две созданные им временные базы удалены; исходная база не использовалась для таблиц приложения.

Сборка, vet с тегами integration/e2e и golangci-lint прошли; 0 замечаний линтера.
Матрица прав: 107 защищённых операций, 5 публичных, 6 ролей. Контракты: 24 схемы базы origin/main,
несовместимых изменений 0. PowerShell-обвязка проверена на lifecycle временной базы и фильтре `-Run`.

Race detector не запускался: `CGO_ENABLED=0`. Конкурентные фитнес-тесты выполнялись.
Kafka/DLT, браузерный e2e, Kubernetes, нагрузка, хаос, восстановление стенда и публикация не проверялись.
