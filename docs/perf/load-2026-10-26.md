## Исправления, проверенные нагрузкой

- k6 сохраняет cookie между итерациями. Разгон и пауза 10–20 с при ошибке
  входа учитывают общий лимит `/auth/` в 2 запроса/с с одного IP.
  Статус и путь ошибочного ответа выводятся один раз на VU без query и токенов.
- Пустой замер не проходит: нужны запросы экранов и успешные экраны от всех 50 VU.
- Список заявок BFF запрашивает `GET /requests?summary=true`. Варианты исключаются
  из SQL-результата для этого режима; полный ответ остаётся поведением API
  по умолчанию и доступен в карточке заявки. До исправления 38 заявок занимали
  8 834 285 байт и превышали лимит BFF в 8 МиБ, вызывая 503. После исправления
  список из 100 заявок занимает 57 290 байт.
- Регрессионные тесты проверяют вариант больше 8 МиБ, компактный список,
  сохранение полного содержимого карточки и изоляцию другой клиники.

Это измерение конкретного локального синтетического стенда. Результаты
GitHub Actions и Kubernetes/PITR приводятся отдельно в [сводке приёмки](acceptance-status.md).
