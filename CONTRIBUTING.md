# Правила разработки

Проект: АС распределения компонентов донорской крови. Go, микросервисы, Kafka, PostgreSQL, Keycloak, Kubernetes.
Владелец: AlchemistBro. Язык документации — русский. Идентификаторы в коде — английские.

## С чего начать

1. `docs/PLAN.md`: цели, решения владельца, этапы, стек.
2. Канон предметной области: `docs/domain/glossary.md`, `docs/domain/requirements.md`, `docs/domain/obligation-states.md`,
   `docs/domain/context-map.md`. Это источник истины о предметной области; изменения — только через ADR.
3. Архитектура: `docs/architecture/*.md` и все `docs/adr/*.md`.
4. Текущий этап: `docs/tasks/NN-*.md` (первый незакрытый в таблице статусов `docs/PLAN.md`), работа по чеклисту.

## Правила канона

- Идентификаторы требований `FR001–FR052`, `NFR001–NFR017`, объектов `O01–O18`, систем `C01–C04`, интеграций
  `ИНТ-01…ИНТ-05`, классов данных `K1–K3`, подсистем `ФП1–ФП4`, поддоменов `S01–S03` зафиксированы.
- Статусы обязательства O07 и переходы — только из `docs/domain/obligation-states.md`.
- Имена сущностей и полей БД — из словаря данных ПР6 (`docs/architecture/data-model.md`), в snake_case.
- В системе нет ФИО, СНИЛС и иных идентификаторов лиц. Пациент — только `patient_case_no` (K1). Прогноз ЧС
  проходит белый список полей. Поля для ПДн не создавать даже «на будущее».
- Все числовые нормативы и клинические правила подбора синтетические (ADR-0010). В коде и UI пометка «демо».
- Терминология: «единица компонента крови», «обязательство на передачу», «закрепление единицы», «реестр дефицита»,
  «заявка», «защищённый объём», «водяной знак». Синонимы не использовать.

## Архитектурные правила

- Сервис пишет только в свою БД. Чужие данные — проекция из событий с версией. Межсервисных JOIN и общих таблиц нет.
- Между сервисами только Kafka через `libs/messaging` (outbox → relay → topic → inbox). Прямой `kgo.Produce`
  из бизнес-кода запрещён. Единственный синхронный вызов между сервисами — `transfer → inventory` статус единиц (ADR-0004).
- Контракты сообщений и HTTP только в `libs/contracts` (Go-типы + JSON Schema + OpenAPI). Изменение контракта —
  обратно совместимое, со схемой и тестом совместимости; иначе новая версия типа.
- Один `go.mod`. Пакеты сервиса лежат в `services/<name>/internal/...`; компилятор запрещает их импорт из других сервисов.
  Общий код — в `libs/`. Тест `tools/archtest` проверяет, что `libs/` не импортирует `services/`.
- Доменная логика — чистые пакеты без зависимостей от pgx/kafka/http (`internal/domain`). Приложение
  (`internal/app`) оркестрирует транзакции. Адаптеры (`internal/adapters/{postgres,kafka,http}`) реализуют порты.
- Транзакция бизнес-операции включает: изменение агрегата, запись в outbox, запись аудита. Сетевых вызовов внутри
  транзакции нет. Порядок блокировок в `transfer`: строка Остатка, затем строка O07.
- Каждый переход статуса — `UPDATE … WHERE status = :expected` (CAS). Повтор команды идемпотентен по ключу.
- Каждый сервис отдаёт `/healthz`, `/readyz`, `/metrics`, OpenAPI `GET /openapi.yaml`, трассы и логи с `correlation_id`.

## Правила кода Go

- Go 1.27, `gofmt`, `golangci-lint` по `.golangci.yml`. Ошибки оборачиваются `fmt.Errorf("…: %w", err)`, без panic в проде.
- Структура сервиса: `cmd/<name>/main.go` (только сборка зависимостей), `internal/domain`, `internal/app`,
  `internal/adapters`, `internal/api` (сгенерированный `oapi-codegen` + хендлеры), `migrations/` (goose, embed), `sqlc/`.
- Контекст и таймауты везде. Фоновые воркеры останавливаются по `ctx` и `errgroup`.
- Время только через интерфейс `Clock` (для тестов таймеров и сроков).
- Деньги не нужны, объёмы в мл — `int64`, расчётные доли — `float64` с явным округлением, как в ПР6 (`numeric`).
- Комментарии к пакетам и неочевидным решениям — русские, краткие, объясняют «почему», ссылаются на FR/NFR/ADR.
- Логи структурные (`slog`), без ПДн и без `patient_case_no`. Спецификация замены единицы (фенотип) в логи не попадает.

## Правила тестов

- Юнит-тесты домена без Docker. Интеграционные — на реальных PostgreSQL и Kafka через `testcontainers-go`,
  помечены `//go:build integration`, запускаются `task test:integration`.
- Фитнес-тесты саги (четыре гонки, kill -9 шлюза, дубль доставки) обязаны быть зелёными на каждом этапе начиная с 1.
- Новый эндпоинт → тест авторизации (роль без права получает 403) и тест контракта по OpenAPI.
- Проверка «тест действительно проверяет»: перед закрытием этапа отключить ключевое правило (например, уникальный
  индекс или сверку) и убедиться, что соответствующий тест падает. Результат записать в задачу этапа.

## Правила UI (`services/web`)

- Серверный рендеринг `html/template`, HTMX 2 из `static/vendor`, без сборщиков. Стиль — `docs/ui/style-guide.md`.
- Все формы работают без JavaScript (HTMX только улучшает). Ошибки сервера — человеческим русским языком.
- Каждый экран показывает роль, клинику и время последнего обновления запаса (NFR015).
- Чтение `patient_case_no` на экране — только ролям заявки и всегда с записью в аудит (NFR016).

## Рабочий цикл

1. Следующий пункт чеклиста этапа. Большой пункт разбивается на подпункты в том же файле.
2. Сначала тест (красный), затем реализация, затем рефакторинг. Для саги тесты Java-прототипа переносятся первыми.
3. `task fmt lint test` перед каждым коммитом. `task ci` перед закрытием этапа.
4. Коммиты на русском, в повелительном наклонении, одна смысловая правка: «Этап 1: outbox-ретранслятор с остановкой на первой ошибке».
5. Отклонение от ADR или канона → сначала новый ADR в `docs/adr/` со статусом «предложен», затем код.
6. Закрывая этап: обновить `docs/PLAN.md` (таблица статусов), README (возможности, схема), схемы в `docs/architecture/`.
7. Открытые вопросы записываются в `docs/PLAN.md` раздел 8 вместе с принятым допущением.

## Команды

Все команды через Taskfile (`task --list`). Ключевые:

```
task up            # compose: платформа + сервисы + имитаторы
task down          # остановить и удалить тома
task dev:<svc>     # запустить один сервис локально против compose-платформы
task test          # юнит-тесты с -race
task test:integration
task test:e2e      # smoke-сценарии на поднятом compose
task bench:plan    # бенчмарк NFR002
task lint fmt gen  # golangci-lint, gofmt, oapi-codegen + sqlc
task ci            # всё, что делает GitHub Actions, локально
task k8s:up        # kind + kustomize overlay local
task k8s:drill     # учение восстановления PITR
```

## Чего не делать

- Не добавлять технологии вне `docs/PLAN.md` раздел 5 без ADR (service mesh, GraphQL, ORM, Redis, фронтенд-фреймворки).
- Не делать «общую библиотеку домена» между сервисами. Общие только контракты и платформенные `libs/`.
- Не писать в чужую базу «для простоты», не читать чужую таблицу напрямую.
- Не хранить секреты в репозитории. В compose — `.env.example`, в k8s — Secret из `kustomize secretGenerator` с демо-значениями.
- Не ослаблять тесты гонок ради зелёного CI.
