# Сценарии устойчивости

`task chaos` работает против уже поднятого отдельного compose-стенда. Используется существующая e2e-обвязка:
новая единица в АИСТ-М, ожидание собственных копий inventory/transfer, открытие и подтверждение задания,
проверка статуса и числа заказов у C03.

- 50 одновременных подтверждений одной единицы: один успешный ответ и одно активное закрепление.
- Пауза Kafka на 60 секунд: подтверждение сохраняется, команда остаётся в outbox; после возобновления один заказ.
- Потерянный ответ C03: сверка находит созданный заказ и не создаёт второй.
- Остановленный шлюз: после запуска читает сохранённую команду.
- Убийство шлюза в середине заказа: после истечения аренды продолжает сверку, один заказ.

Нельзя запускать против рабочего окружения. Скрипт не перезапускает Docker Desktop, WSL, VPN и маршруты.
Сценарии не выполнялись по решению владельца; их компиляция не подтверждает прохождение проверок.
Дополнительные сценарии остановки transfer во время транзакции и деградации Keycloak остаются в плане приёмки.
